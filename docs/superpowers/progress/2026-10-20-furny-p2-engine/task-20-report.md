## Design decisions (please confirm)

1. **Params zod parse is done by the bus, not inside `defaultPipeline`.** The pinned `Pipeline` signature has 4 args and no prefix, but the `invalid_params` key needs `messageKeyPrefix`. The bus therefore parses `paramsSchema` once per execute (for every pipeline, which is preflight I5's second option), refuses with `{code:'invalid_params', messageKey:'<prefix>.invalid_params', params:{command, field, issue}}`, and passes the *parsed* value to the pipeline and into `lastParams`. `defaultPipeline` = validate -> single `create` -> `CommandAbort` becomes an error result; other exceptions propagate. Task 21's `planPipeline` need not parse (parsing again is harmless).
2. **Atomicity.** The pipeline runs against the immutable document; label params, merge key and changed-id extraction are computed before any state is touched; the commit is one synchronous block. Refusals, aborts, zod failures and crashes leave doc, both stacks, the open transaction, merge state and `seq` untouched and notify nobody (tested for each, including an unexpected `Error`, which propagates).
3. **Replace merge**: `base = apply(doc, top.inversePatches)`, pipeline re-run on `base`; `getContext(base)` (the document the pipeline runs on). A failed re-run returns the error and leaves the merged state. The `merge` event's patches are `top.inversePatches ++ new.patches` (so `apply(prevDoc, patches) == doc` and `changedIds` also covers entities of the replaced sequence). Merge strategy is chosen by the executing command's `mergeMode`.
4. **Commands that change nothing** (zero patches): `ok` result with empty `changedIds`; no entry, no event, redo stack survives; the top entry is sealed (a different command ended the burst), except a no-op compose merge which leaves the burst running.
5. **`history: false`**: applies, no entry, seals the top, clears redo (literal reading of 04 §6.2-1; note for P4: view-only commands routed with `history:false` will clear redo). `merge:true` with `history:false` never merges.
6. **Transactions**: `begin` seals the top entry; commands apply immediately and are recorded as steps; inside a transaction stacks are not touched (redo is cleared at commit, kept on rollback). Commit pushes one sealed entry (`type 'transaction'`, label from begin) built from the `history` steps only, and emits `commit` (only when an entry exists). **Nested levels use savepoints**: `rollbackTransaction` at depth > 1 rolls back to the matching begin and closes only that level (at depth 1 it is the whole transaction, as in the spec). This makes `transaction()` composable (an outer fn can catch an inner failure and continue) instead of silently continuing outside a transaction. `undo()`/`redo()` return `false` and `canUndo()/canRedo()` are false while a transaction is open; `reset()` throws then; commit/rollback with no open transaction throw.
7. **`transaction(label, fn, labelParams?)`**: rolls back and rethrows if `fn` throws; if any execute inside returned an error (even if `fn` ignored it) it rolls back and throws `CommandFailedError` (`.error` = the first unforgiven failure). A listener error raised by the rollback event cannot mask the original error. `fn` must be synchronous.
8. **Subscriber policy (isolate, notify the rest, rethrow)**: every subscriber gets every event in subscription order even if others throw; afterwards a single error is rethrown as is, several as `AggregateError`, from the call that produced the event. The change is already committed when that happens (the throw reports the listener, not the command). Unsubscribing (self or another) during delivery is safe: a removed subscriber is not called for the event in flight, a newly added one starts with the next event. Events produced by a listener that re-enters the bus are queued, so all subscribers see commit order. Documented in the `bus.ts` header; tested.
9. Entries are immutable frozen objects replaced on update (`seal`/merge), so entries handed to subscribers or `history()` never change underneath them. `history()` returns copies of the arrays.
10. Small additions beyond the pinned config: `now?: () => number` (clock for `HistoryEntry.at`, injectable for tests; default `Date.now`), `transaction`'s optional third arg, `CommandFailedError`, `shouldAutoFreeze` export (so Task 21's pipeline can use the same policy), `ParamsOf`/`ResultOf`. `maxHistory` must be a positive integer (RangeError).
11. Caveat: with auto-freeze on (dev/tests) the first execute also freezes the unchanged subtrees of the `initial` object the caller passed (mutative freezes shared parts). The root `initial` object itself is not frozen until replaced.

Important

Empty entry after a no-op replace merge: when the re-run produces zero patches, `commitMerge` sets the document to the re-run result (the start of the sequence), drops the top entry and emits `merge` with `entry: null` (documented on `BusEvent.entry`; event patches are the old inverse patches so `apply(prevDoc, patches) == doc`). `canUndo` is false afterwards; the entry below is sealed so the next drag starts a new entry.
