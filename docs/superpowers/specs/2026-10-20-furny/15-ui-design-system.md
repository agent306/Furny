# 15 — UI Design System

Read the master document, `01`, `02`, `03` and `09` first. This file is normative for **visual tokens, the shared component catalogue, layouts, form/toast conventions, accessibility, i18n, formatting, icons, theming and print styles**. Page-level UI is in `10-customer-app.md` (customer) and `11-admin-app.md` (staff). Editor canvas internals (plan editor, furniture builder) are in `05` and `07`; this file only provides the tokens and layout slots they use.

Precedence reminder: master > 02 > 03 > 09 > this file. If this file and 10/11 disagree on a component's API, **this file wins**.

---

## 1. Visual direction

- **Mood:** calm, quiet, workshop-honest. A warm "linen and oak" neutral palette, one accent (**Walnut** brown in light theme, **Oak** in dark theme) used for primary actions, focus rings and the current step. No gradients except the subtle wood-grain empty-state motif (§13). No drop-shadow-heavy cards: hierarchy comes from spacing, borders and type weight.
- **Density:** customer app is comfortable (body 16 px, 44 px touch targets everywhere). Admin app is compact on desktop (body 14 px, table rows 40 px) but switches to comfortable sizing below 768 px.
- **Status colour is never the only signal:** every status uses colour + text label (+ icon where space allows).
- **Light and dark themes** are first-class (§11). The plan editor canvas follows the theme, but every **export** (PNG/SVG/PDF/print) uses the light palette.
- **Product name** is never hard-coded: use `usePage().props.app.name` (master header).

## 3. Tokens — `resources/css/app.css`

Tailwind v4 CSS-first config. All colours are OKLCH. shadcn-vue components read the shadcn variable names (`--background`, `--primary`, `--accent`, …); app code uses the Tailwind utilities generated by `@theme inline` (`bg-background`, `text-muted-foreground`, `bg-success-subtle`, `fill-room-bedroom`, …). **Never** use raw Tailwind palette colours (`bg-blue-500`, `text-gray-600`) in app code; ESLint rule `tailwindcss/no-arbitrary-value` is not available for v4, so a Vitest test (`resources/js/__tests__/no-raw-palette.test.ts`) greps `resources/js/**/*.vue` for `/\b(bg|text|border|fill|stroke|ring)-(slate|gray|zinc|neutral|stone|red|orange|amber|yellow|lime|green|emerald|teal|cyan|sky|blue|indigo|violet|purple|fuchsia|pink|rose)-\d{2,3}\b/` and fails on any match (files under `components/ui/` are exempt until regenerated).

Note on `--accent`: in shadcn-vue, `accent` is the **subtle interactive surface** (hover/active background of menu items, ghost buttons). The brand accent colour of the product is `--primary`. Do not repurpose `--accent`.

### 3.2 Typography scale

Font: **Inter Variable** for all UI text; **JetBrains Mono Variable** for dimensions in `DimensionText`/`LengthInput`, catalog codes, order/quote numbers in tables, JSON viewers. Numbers in tables and money use `tabular-nums` (`.tabular` or Tailwind `tabular-nums`).

| Role | Tailwind classes | Size / line-height | Weight | Usage |
|---|---|---|---|---|
| Display | `text-3xl font-semibold tracking-tight` | 30/36 | 600 | Welcome page hero only |
| H1 (page title) | `text-2xl font-semibold tracking-tight` | 24/32 | 600 | `PageHeader` title |
| H2 (section) | `text-lg font-semibold` | 18/28 | 600 | Card/section titles |
| H3 (subsection) | `text-base font-semibold` | 16/24 | 600 | Sub-headings, dialog titles |
| Body (customer) | `text-base` | 16/24 | 400 | Customer app default |
| Body (admin) | `text-sm` | 14/20 | 400 | Admin app default (≥ 768 px); `text-base` below |
| Small / meta | `text-sm text-muted-foreground` | 14/20 | 400 | Captions, timestamps |
| Micro | `text-xs` | 12/16 | 500 | Badges, chart axes, editor status bar |
| Mono dimension | `font-mono text-sm tabular-nums` | 14/20 | 450 | Dimensions, codes |

Rules: max 2 weights per screen region (400 + 600, 500 only for badges/labels). Paragraph max width `max-w-prose` (65ch). Never below 12 px. Phone (< 768 px) page title is `text-xl`.

### 3.3 Spacing, sizing, radii, shadows, z-index

- **Spacing:** Tailwind default 4 px scale (`--spacing: 0.25rem`). Conventions: page gutter `px-4 sm:px-6 lg:px-8`; vertical rhythm between page sections `space-y-8` (customer) / `space-y-6` (admin); card padding `p-4 sm:p-6`; form field gap `space-y-4`; inline control gap `gap-2`.
- **Control heights:** customer `h-11` (44 px) for buttons/inputs at all breakpoints; admin `h-9` (36 px) at ≥ 768 px and `h-11` below. Implemented with the `size` prop of `Button`/`Input` (`size="default"` = h-9, `size="lg"` = h-11): `AppShell` provides `density` via `provide('density', 'comfortable' | 'compact')`, and the composable `useControlSize()` returns `'lg'` for comfortable and `'default'` for compact; pages bind `:size="controlSize"`. No wrapper components around shadcn `Button`/`Input`.
- **Radii:** `rounded-sm` badges/chips, `rounded-md` controls, `rounded-lg` cards/dialogs, `rounded-xl` sheets/media, `rounded-full` avatars/status dots.
- **Shadows:** cards `shadow-xs` (plus border); dropdowns/popovers `shadow-md`; dialogs/sheets `shadow-overlay`; editor floating toolbars `shadow-lg`.
- **Z-index scale** (Tailwind utilities; document in `resources/js/lib/zIndex.ts` as constants for editor code):

| Layer | Value | Utility |
|---|---|---|
| Editor canvas internal layers | 0–9 | `z-0`…`z-[9]` (05/07 manage) |
| Sticky table headers, sticky action bars | 10 | `z-10` |
| Editor floating toolbars / inspector overlay (tablet) | 20 | `z-20` |
| App header / mobile bottom tab bar | 30 | `z-30` |
| Sidebar (offcanvas) | 40 | `z-40` |
| All Reka portals: popover, dropdown, select, tooltip, dialog, sheet, drawer | 50 | `z-50` (shadcn default; stacking among portals follows DOM order) |
| Lightbox (opens above dialogs) | 60 | `z-[60]` |
| Toasts (vue-sonner) | 100 | `z-[100]` |

### 9.10 `FileDropzone` (`components/media/FileDropzone.vue`)
Generic upload dropzone for **every** browser upload (including blueprint imports, purpose `blueprint_source`, 06 §1.1), implementing the **upload-intent flow of `13` §11**.
Props: `purpose: UploadPurpose`, `target?: { type: string; id: string } | null` (authorisation target, e.g. the order for `message_attachment`), `accept: string[]` (MIME list), `maxSizeBytes: number`, `maxFiles: number`, `multiple?: boolean`, `modelValue: UploadedFileRef[]`, `disabled?`, `capture?: 'environment' | 'user'` (adds "Take photo" on touch devices via `<input type="file" accept="image/*" capture>`), `compressImages?: boolean` (§9.12), `label?: string`, `hint?: string`.
Emits: `update:modelValue(files: UploadedFileRef[])`, `uploading(boolean)`.

```ts
type UploadPurpose = 'blueprint_source' | 'message_attachment' | 'production_photo' | 'issue_photo' | 'delivery_photo' | 'avatar' | 'business_logo'
  | 'material_texture' | 'finish_texture' | 'hardware_image' | 'plan_thumbnail' | 'project_cover' | 'furniture_thumbnail' | 'preset_thumbnail';   // exactly the 14 values of 13 §11.1 (generated from the PHP enum)
interface UploadedFileRef { uploadId: string; name: string; size: number; mime: string; previewUrl: string | null /* object URL or server previewUrl */ }
```

Flow per file (`lib/upload.ts::uploadWithIntent(file, purpose, target, onProgress, signal)`):
1. Optional client compression (§9.12) **before** step 2 (the declared size must equal the uploaded bytes).
2. Client checks type (by `file.type`, fallback extension) and size against the purpose limits of `13` §11.1 → inline errors `uploads.errors.type` "{name}: this file type isn't allowed.", `uploads.errors.size` "{name} is larger than {max}.", `uploads.errors.count` "You can attach up to {max} files."
3. `POST api.uploads.presign` `{ purpose, filename, size, contentType, target }` → `{ uploadId, url, headers }` (422 / 429 shown inline).
4. `XMLHttpRequest` PUT to `url` sending **exactly** the returned `headers` (progress → per-file bar; Abort via AbortController; **Retry** restarts from step 3).
5. `POST api.uploads.confirm` → `202 { uploadId, status: 'processing' }`; poll `api.uploads.show` every 1 s (max 60 s) until `ready` (use `previewUrl` when given) or `rejected` (show `t('uploads.errors.' + reasonCode)`, e.g. `upload_type_not_allowed`, `upload_image_too_large`, `upload_size_mismatch`).
6. Emit the `UploadedFileRef`; the parent form submits `uploadIds: string[]`; the consuming Action attaches the media (`13` §11.3 step 7).

UI: dashed `border-2 border-dashed rounded-xl` area (min-h 160 px desktop, 120 px phone), `upload-cloud` icon, `uploads.drop_here` "Drag files here or **browse**", hint (types + max size). Drag-over `border-primary bg-primary/5`. File list: thumbnail / file icon, name (truncate), size, progress, status ("Preparing…", "Uploading 45 %", "Checking…", "Ready", error), remove (`aria-label` "Remove {name}"). The area is a `button` (Enter/Space opens the picker); `Ctrl+V` pastes images when focused. Submit buttons of the parent form stay disabled while `uploading` is true.

### 9.12 Client-side image compression (`composables/useImageCompression.ts`)
`compressImage(file: File): Promise<File>`:
1. If `file.type` is not an image → return unchanged.
2. Decode with `createImageBitmap(file, { imageOrientation: 'from-image' })` (applies EXIF rotation). If decoding throws (e.g. HEIC on browsers without support) → return the **original** file (server converts HEIC → JPEG per `02` §10).
3. If longest side ≤ 2560 and `file.type === 'image/jpeg'` and `file.size ≤ 1.5 MB` → return unchanged.
4. Scale so the longest side ≤ **2560 px** (never upscale); draw on `OffscreenCanvas` (fallback `<canvas>`) with white background (flattens PNG transparency), `imageSmoothingQuality = 'high'`.
5. Encode `image/jpeg` quality **0.85**; filename extension replaced by `.jpg`. Re-encoding strips EXIF (incl. GPS) — intended for privacy.
6. If the result is larger than the original and the original is an accepted type ≤ max size → upload the original.
Runs sequentially (one image at a time) to bound memory on phones; shows "Preparing…" status per file.

## 10. Forms conventions

### 10.1 Mechanics
- **Simple forms** (one submit, no client-side derived state): Inertia v3 `<Form>` component (`action`, `method`, `#default="{ errors, processing, isDirty, wasSuccessful }"`), with Wayfinder-generated action objects: `<Form v-bind="ProjectController.store.form()">`.
- **Complex forms** (dynamic arrays, live totals, multi-step): `useForm<T>()` with explicit TS type, `form.transform()` for payload shaping, `form.submit(route)`.
- Field names in payloads are **camelCase** (FormRequests validate camelCase keys and map to snake_case columns in the Action/Data layer), except Fortify/`13` auth forms, which use the names given in `13`. Array fields use dot paths in errors (`items.2.quantity`).
- Every field: `<Label for>` + control with `id`, `aria-invalid` when error, `aria-describedby` → hint and `InputError`. Required fields marked with `*` (visually) + `aria-required`; optional fields are not marked "(optional)" except in customer forms where most fields are required (then mark optional ones).
- Server is the source of truth for validation. Client-side checks are limited to: required, length limits, number ranges, file type/size, `LengthInput`/`CurrencyInput`/`PhoneInput` parsing. Client messages use the same translation keys as server messages where possible.
- **Error display:** inline under field; plus, when the response has errors on fields not shown on the current step/tab, a top-of-form `Alert` (destructive) listing them with anchor links; focus moves to the first invalid field after submit (`nextTick` → `document.querySelector('[aria-invalid=true]')?.focus()`).
- **Domain errors** (409 `invalid_transition`, 422 with `code`): the server returns them as a validation error on a pseudo-field `_error` (Inertia) or JSON `{ code, message }` (API). UI shows `_error` in a destructive `Alert` above the actions and a toast. HTTP 409 on Inertia requests is converted server-side into a redirect back with `flash.error` (see 14) so the page reloads current state.
- **Submit buttons:** disabled while `processing`; show a 16 px spinner (`loader-circle` animate-spin) left of the label and keep width stable; label does not change. Double submission impossible (`processing` guard). Long actions (> 400 ms expected) keep the dialog open until the response.
- **Unsaved changes:** forms with `isDirty` warn on Inertia navigation (`router.on('before', …)` → `useConfirm`) and `beforeunload`.
- **Dialogs with forms:** close on success (`onSuccess`), stay open on error; `preserveScroll: true` and `preserveState: true` for in-page actions; `only: [...]` partial reloads where the page defines them.

### 10.2 Optimistic updates (only these)
Mark notification read / all read; mark message thread read; append own message ("Sending…"); toggle notification preference cell; reorder presets/templates (revert on failure). Everything that changes order state is **pessimistic** (wait for server).

### 10.3 Toasts (vue-sonner)
- Server → client: controllers set `flash.success|error|info|warning` with **translated strings** (PHP `trans_icu()`, §15.3). `AppShell` watches `page.props.flash` and calls `toast.success(...)` etc. once per visit (dedupe by a per-visit id `flash.id` if present; otherwise by value + `page.url`).
- Client-only toasts: copy actions, upload failures, network errors (`errors.network` "Connection problem. Please try again."), real-time notifications.
- Durations: success/info 4 s, warning 6 s, error 8 s (errors also have a close button). Max 3 visible. Never use toasts for form field errors or for anything the user must act on (use `ActionPanel`/`Alert`).
- Placement: `bottom-right` (≥ 768), `top-center` (< 768), offset above the mobile tab bar.

### 10.4 Loading & empty states
- Initial page data comes from Inertia props (no spinner). Heavy props are **deferred** (`Inertia::defer()`) and wrapped in `<Deferred data="…">` with `LoadingState` fallback of matching shape.
- Navigation progress: Inertia progress bar colour `var(--primary)`, delay 250 ms.
- Buttons triggering visits show their own spinner; never block the whole page.
- Every list has an `EmptyState` with a primary action when the user can create something, and a distinct "No results for these filters" state (icon `search-x`, button "Clear filters") when filters are active.

## 11. Theming (light / dark)

**Decision:** appearance is a **device-level** preference (not stored on the user record): values `light | dark | system`, default `system`.
- Persisted in `localStorage['fs:appearance']` **and** a cookie `appearance` (1 year, `SameSite=Lax`, not HttpOnly) so `app.blade.php` can render `<html class="dark">` server-side and avoid a flash. The Blade root also contains an inline script (≤ 15 lines, before CSS) that applies `system` via `matchMedia('(prefers-color-scheme: dark)')`.
- `useTheme()` → `{ appearance: Ref<'light'|'dark'|'system'>, resolved: Ref<'light'|'dark'>, setAppearance(v) }`; listens to `matchMedia` changes when `system`; storage access wrapped in try/catch.
- `<meta name="theme-color">` updated to the resolved `--background` hex (light `#fbfaf7`, dark `#1d1a17`; precomputed constants in `lib/theme/meta.ts`).
- Toggle lives in `UserMenu` (customer + staff) and the admin top bar.
- PDFs, emails and exports are always light.

## 12. Real-time UI conventions

- `lib/echo.ts` configures Echo with Reverb (`01` §8). Composables: `useUserChannel()` (`users.{id}`: `NotificationCreated`, `AiCreditsChanged`), `useOrderChannel(orderId, handlers, { internal?: boolean })` (staff pages pass `internal: true` to also join `orders.{id}.internal`, `13` §8.10), `useImportChannel(importId, handlers)`, `useStaffChannel(handlers)` (`staff`), `useDesignChannel(designId, handlers)`.
- Each composable returns `{ connected: Ref<boolean> }` and leaves the channel on unmount. When `connected` is false for > 5 s, pages that depend on live state start `usePoll(30_000, { only: [...] })` (Inertia) and stop it on reconnect (`01` §8).
- On events that change page data, prefer **partial reloads** (`router.reload({ only: ['order', 'timeline'] })`) over patching local state, except messages and notifications which are appended locally. Reloads are throttled to 1 per 2 s per page.
- A small connection indicator is **not** shown to customers; staff order pages show a grey dot "Live updates paused" in the header when disconnected.

## 14. Accessibility (WCAG 2.1 AA — mandatory)

1. **Contrast:** text ≥ 4.5:1 (large text ≥ 3:1), UI component boundaries & focus indicators ≥ 3:1, in **both** themes.
2. **Keyboard:** every interactive element reachable and operable by keyboard in logical order; no keyboard traps except modal dialogs (which trap by design and close on Esc). Visible focus (`:focus-visible` 2 px `--ring`, offset 2). Custom widgets follow WAI-ARIA APG patterns via Reka primitives.
3. **Dialogs/sheets/drawers:** Reka `Dialog` semantics (`role="dialog"`, `aria-modal`, labelled by title, described by description); initial focus on first field (forms) or the safest button (confirmations); focus returns to the trigger on close.
4. **Route changes:** after each Inertia navigation, focus moves to `#main` heading (`h1` with `tabindex="-1"`), and the document `<title>` is `{page title} · {app name}` (Inertia `<Head>`). A polite live region announces the page title.
5. **Live regions:** toasts (`aria-live="polite"`, errors `assertive` via sonner), autosave status (`polite`), import progress (`polite`, throttled to stage changes), new messages (`polite`: "New message from {name}").
6. **Touch targets:** ≥ 44 × 44 px for all interactive elements at < 1024 px and everywhere in the customer app; admin desktop dense controls ≥ 32 × 32 with ≥ 8 px spacing (WCAG 2.5.8 AA 24 px satisfied).
7. **Reduced motion:** honour `prefers-reduced-motion` (§3.1 CSS; 3D camera transitions become instant — 05/07 read `useReducedMotion()`).
8. **Forms:** labels for every control; errors linked via `aria-describedby`; don't rely on placeholder as label; error summary on submit (§10.1).
9. **Images:** meaningful `alt` (design name, "Production photo {n} — {stage}"); decorative images `alt=""`.
10. **Colour independence:** status = colour + text/icon; diff highlighting in 3D has a legend and the `DiffList` text; confidence colours in import review also use line style (solid/dashed/dotted — 06).
11. **Language:** `<html lang>` = user locale; numbers/dates via `Intl`.
12. **Zoom/reflow:** usable at 200 % zoom and 320 px width without horizontal scroll (editors excepted: canvas pans).
13. **Testing:** the Playwright accessibility suite (`@axe-core/playwright`, `16 §11`) runs axe-core on: welcome, login, dashboard (customer), project page, order page (states `quoted`, `completed`), notifications, settings, admin dashboard, admin order detail, catalog list — zero `serious`/`critical` violations (`16`).

## 15. Internationalisation

### 15.1 Decision
**Custom thin i18n layer on `intl-messageformat` (ICU MessageFormat)** — not `vue-i18n` (its message syntax is not ICU and lacks `select`), not `laravel-vue-i18n` (Laravel `:param` syntax, no ICU). ICU is required by `09` §10 (`select`, plurals). Only `en` ships (master §4.2) but every string goes through i18n.

### 15.2 Source of truth: PHP lang files
- Strings live in `resources/lang/en/{namespace}.php` returning nested arrays; **values are ICU messages** (`{name}`, `{count, plural, one {# item} other {# items}}`, `{reason, select, quote_declined {…} other {…}}`).
- Exception — Laravel-format namespaces (consumed only by Laravel itself with `:attribute` placeholders): `validation`, `passwords`, `pagination`, `auth`. These are **not** exported to the frontend. Validation messages reach the browser already rendered (Inertia errors). `13`'s auth messages (`auth.inactive`, `auth.session_expired`, `auth.errors.*`) live in `auth.php` with Laravel `:param` placeholders and are rendered server-side with `__()` (flash messages / validation errors); strings rendered in Vue on auth pages live in `auth_ui`.
- Namespaces (one file each): `common, a11y, auth_ui, legal, onboarding, account, dashboard, projects, plans, imports, designs, orders, quotes, proposals, production, messages, notifications, settings, credits, help, uploads, units, money, phone, errors, states, changes, parts, hardware, plan_editor, engine, builder, admin, catalog, presets, templates, reports, audit, system, staff, customers, roles, ai, issues, calls, delivery, estimates, emails, pdf`. (05 owns `plan_editor`; 04 owns `engine` (every `engine.*` issue/command/label key); 07 owns `builder`, `parts`, `hardware`, `changes`; 12 owns `notifications` and `emails`; 18 owns `ai` (`ai.error.{code}`) and `credits`.)
- Key naming: `{namespace}.{area}.{item}` with `snake_case` segments, max depth 4. Common areas: `actions.*` (button labels, imperative: "Save changes"), `fields.*` (labels), `hints.*`, `errors.*`, `empty.*` (`empty.title`, `empty.body`), `titles.*` (page titles), `toasts.*`, `confirm.*`. Example: `orders.actions.accept_quote` = "Accept quote".
- **Dynamic keys** (enum labels) follow fixed patterns so the checker can enumerate them: `orders.states.{state}`, `orders.states_customer.{state}`, `orders.states_customer_short.{state}`, `orders.steps.{key}`, `orders.cancel_reasons.{reason}`, `orders.call_outcomes.{outcome}`, `imports.statuses.{status}`, `imports.stages.{stage}`, `imports.error.{code}` (06 §14), `quotes.statuses.{status}`, `quotes.line_kinds.{kind}`, `production.stages.{key}`, `projects.property_types.{type}`, `plans.room_types.{type}`, `catalog.board_types.{type}`, `catalog.hardware_categories.{category}`, `notifications.events.{event_key}.{title|body|label|description}`, `messages.system.{event_key}`.

### 15.3 Export to the frontend
- Artisan command `php artisan i18n:export` (class `App\Console\Commands\ExportTranslations`): loads every ICU namespace for every locale in `config('app.supported_locales')` (`['en']`), flattens to dot keys, validates each message parses as ICU (via PHP `MessageFormatter::create`; fails with the offending key), writes `resources/js/lang/generated/{locale}.json` (sorted keys) and `resources/js/lang/generated/manifest.json` `{ "en": "<sha1 of file>" }`. Generated files are committed; CI runs the command and fails if `git diff` is non-empty (same policy as TS types, `01` §6).
- Dev: a tiny Vite plugin `vite/i18n-watch.ts` watches `resources/lang/**/*.php` and runs `php artisan i18n:export` on change (debounced 300 ms), then triggers full reload.
- Shared prop `i18n = { locale, hash }` where hash = manifest entry; the client bundles the JSON via `import.meta.glob('../lang/generated/*.json')` (lazy per locale) and, if `hash` differs from the bundled manifest (stale deploy), forces `window.location.reload()` once.
- PHP-side rendering of ICU strings (notifications, PDFs, flash messages, system message previews): helper `trans_icu(string $key, array $params = [], ?string $locale = null): string` in `app/Support/I18n/helpers.php` (autoloaded via composer `files`), using `MessageFormatter::formatMessage($locale ?? app()->getLocale(), trans($key, [], $locale), $params)`; missing key → returns the key and logs a warning.

### 15.4 Frontend API (`lib/i18n.ts`, `composables/useI18n.ts`)
- Vue plugin `i18n` installs global `$t` and provides `useI18n()` → `{ t(key: string, params?: Record<string, unknown>): string; has(key): boolean; locale: Ref<string> }`.
- `t` caches compiled `IntlMessageFormat` instances per key; date/number arguments inside messages use the **business locale** for formatting and the **user timezone** (`formats` option with `timeZone`).
- Missing key: returns the key, `console.warn` in dev; a Vitest test (`i18n-keys.test.ts`) scans `resources/js/**/*.{vue,ts}` for literal `t('…')`/`$t('…')`/`labelKey: '…'` calls and asserts each key exists in `en.json`; it also checks every enum-pattern key in §15.2 for every enum value exported in `types/generated.d.ts`.
- ESLint: `vue/no-bare-strings-in-template` enabled (error) with allowlist of punctuation/symbols (`×`, `—`, `·`, `/`, `:`, `%`, `+`); `vue/no-v-html` enabled with the single exception `MessageBody.vue` (`13` §12.6).

### 15.5 Pluralisation & gender
ICU plural categories per CLDR for the locale (`en`: `one`, `other`; always include `other`). Use `#` for the formatted number. Never build sentences by concatenation; pass params.

### 15.6 Formatting (`lib/format.ts`, `composables/useFormat.ts`)
All via `Intl`, locale = `business.locale` (e.g. `en-IN` → lakh grouping), timezone = `auth.user.timezone` (fallback `business.timezone`).
