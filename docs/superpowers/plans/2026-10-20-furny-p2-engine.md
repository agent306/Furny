# P2 — Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the framework-free TypeScript engine (`resources/js/engine`) — units, geometry, plan document/derivation/snapping/commands, furniture templates/generation/validation/commands/diff, BOM, guillotine nesting, pricing — plus the quote-totals TS port, the engine CLI, the Web Worker RPC and all shared fixtures, every behaviour pinned by tests carrying the spec's numbers.

**Architecture:** A pure TS library with one public entry (`engine/index.ts`). Plan and furniture documents are zod-validated JSON edited only through a generic `mutative`-based command bus (undo/redo/merge/transactions); derived plan geometry, furniture models, BOMs, nestings and prices are pure deterministic functions of (document, catalog snapshot). The same code runs on the main thread, in a Web Worker (typed RPC) and in Node through a Vite-bundled CLI (`engine-cli/dist/cli.mjs`) that Laravel spawns.

**Tech Stack:** TypeScript 5.9 (`strict`), zod 4, mutative 2, clipper2-ts 2.0.1-18 (exact), earcut 3.2, flatbush 4.6, nanoid 5, Vitest 3 (+ `bench`, `@vitest/coverage-v8`), Vite 8 (SSR library build), Node 22, yarn 4 (corepack).

**Spec:** `docs/superpowers/specs/2026-10-20-furny-design.md` (master §6, §7) + section files: `01` §5 (engine contract, module tree, catalog snapshot, CLI §5.4, worker §5.5), `03` (all: plan/furniture documents, derived types, keys, migrations, fixtures §6), `04` (all), `07` §0.1, §1–§7, §9, §10, §12 (engine parts), `08` §0–§5, §6.3, §7 (seed data, used as the test catalog), §8.1, §9.2–§9.3, §10; consumed data/APIs from `05` §9 (fixture library), `06` §7.8 (room-name dictionary) and `06` §11.3 (rescale use); `15` §15.2 (lang files); `19` (decisions, informational).

**Environment:** docs/superpowers/plans/2026-10-20-furny-roadmap.md § "Local environment notes" (PHP 8.4 at /usr/local/bin/php, Composer source installs + composer-seed-dist, yarn via corepack, Postgres `furny`/`furny_test`, Redis, no Docker)

**Depends on:** P1 Task 1 (repo scaffold: `package.json` with `packageManager: yarn@4…`, `tsconfig.json` strict with alias `@/*` → `resources/js/*`, Vitest installed with `vitest.config.ts`, flat `eslint.config.js`, Prettier). **Branch:** the executor creates `build/p2-engine` from P1 Task 1's commit (`git checkout -b build/p2-engine <p1-task-1-sha>`) and commits every task there. ## Global Constraints

- Engine purity (01 §5.1, 04 intro): no imports from `vue`, `three`, `@tresjs/*`, DOM globals (`window`, `document`, `HTMLCanvasElement`, `Image`, `localStorage`) or `fetch`; allowed imports: `zod`, `mutative`, `clipper2-ts`, `earcut`, `flatbush`, `nanoid`, and the built-in `Intl` object.
- `clipper2-ts` is imported only by `geometry/clip.ts`, `earcut` only by `geometry/triangulate.ts` (04 §10).
- `engine/index.ts` is the ONLY import path used outside the engine (01 §5.2).
- `ENGINE_VERSION = "1.0.0"` (semver; bump on any output-affecting change) (01 §5.2).
- All lengths are integer millimetres in documents and APIs; derived values are floats and are never written back except through `roundMm(v) = Math.sign(v) * Math.round(Math.abs(v))` (master §6.1, 04 §0.2).
- Angles: degrees normalised to `[0, 360)` with `normDeg`, rounded to 0.01° when written; engine-internal angles are radians unless the name ends in `Deg` (04 §0.2).
- Plan space x → right, y → down; furniture local space origin back-left-bottom, x right, y up, z toward viewer; placement `(x, y)` = centre of the back edge, `rotation` clockwise with front facing +y at 0° (master §6.2).
- Entity IDs inside documents: `{prefix}_{nanoid(10)}`, alphabet `0123456789abcdefghijklmnopqrstuvwxyz`, prefixes `n w o r f x d t s fr p h`, generated by `engine/ids.ts::newId(prefix)` (master §6.3).
- Money is integer minor units; multiplications via `BigInt`; rounding `HALF_UP` at line level; totals are sums of rounded lines (master §6.4, 08 §1).
- Every user-visible message is a translation key `messageKey` + `params`; the engine never produces English sentences (04 §0.2). Exceptions fixed by the spec: `CutListRow.name`, `PriceBreakdown.lines[].description`, CSV export, diff params (08 §3.4, §4, §8.1; 07 §10.1).
- Functions never mutate their inputs; commands mutate only the `mutative` draft (04 §0.2).
- `generateFurniture`, `computeBom`, `nestSheets`, `priceBom` are pure and deterministic: no `Date`, no randomness, no insertion-order-dependent iteration without sorting (07 §3.1, 08 §5.1).
- Never use `Math.round` for furniture part sizes: `fl(v) = Math.floor(v + 1e-6)` (07 notation).
- TS `strict: true`, no `any` (use `unknown` + zod) (master §6.6).
- Pinned versions: zod `^4`, mutative `^2.0`, clipper2-ts `2.0.1-18` (exact), earcut `^3.2`, flatbush `^4.6`, nanoid `^5`, vitest `^3`; Node `>=22.12 <23`; yarn 4, never npm/pnpm lockfiles (01 §1.2).
- Wire format camelCase (CLI JSON in/out) (master §6.6).
- Engine CLI protocol: stdin JSON request, stdout `{ "ok": true, "result": … }` or `{ "ok": false, "error": { code, message, details? } }`, exit code 0 for both, non-zero only on crash (01 §5.4).
- Commit messages: conventional commits ending with the two lines `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01X1MLnD93h3fkmdHrLPbw3u`.

### Plan conventions (decided here; every task follows them)

- **Imports inside the engine are relative** (never `@/…`), so Vitest, the worker and the CLI bundle resolve without alias config. Each task re-exports its public names from `engine/index.ts` (listed under *Produces*).
- **Tests:** `resources/js/engine/<area>/__tests__/<name>.test.ts`; run with `yarn vitest run <path>`. Perf tests live in `__perf__/` and run only via `yarn test:perf` (Task 50).
- **Quality gates (Step 5 of every task):** `yarn eslint <touched dirs> && yarn prettier --check <touched dirs> && yarn vue-tsc --noEmit`.
- **Deterministic ids in tests:** `testIds()` (Task 1). **Seed catalog in tests:** `seedCatalog()` (Task 29).
- **Issue/message key patterns** (spec leaves some open; pinned here): units `engine.units.error.{code}`; derive `engine.plan.derive.{code}`; plan command errors `engine.plan.command.{code}`, labels `engine.plan.command.label.{snake_type}`; snapping `engine.plan.snap.{…}`; conflicts `engine.plan.conflict.{kind}`; **plan validation** `Issue.code = 'plan.{rule}'`, `messageKey = 'engine.plan.issue.{rule}'`; **furniture/BOM issues** `messageKey = 'issues.' + code` (e.g. `issues.furniture.shelf_sag`, `issues.bom.part_exceeds_sheet`); furniture command errors `engine.furniture.command.{code}`, labels `engine.furniture.command.label.{snake_name}`.
- Every module that emits codes exports its code list as a `const` array (e.g. `PARSE_LENGTH_ERROR_CODES`, `PLAN_ISSUE_CODES`, `FURNITURE_ISSUE_CODES`) so Task 51 can check translation coverage.

## Review Focus

1. **Dirty imported plans** (vision output): walls crossing without nodes, collinear overlapping walls, orphan nodes, out-of-bounds openings → derivation never throws or emits NaN, and commands still work without adding new errors. Test: Task 28 `dirty-import.test.ts` (built by `makeDirtyPlan()` of Task 8).
2. **Degenerate/extreme geometry:** 20° wedges, 30 mm walls, coincident directions, coordinates at ±1 000 000 mm, near-coincident nodes (< `EPS`) → finite, CW, simple outputs; Clipper scaling stays exact. Tests: Task 5 (clip at ±1e6), Task 6 (near-coincident endpoints cluster), Task 9 (§3.9 table + `Number.isFinite` sweep).
3. **Catalog drift:** a design saved against a catalog in which its material is archived, an item was deleted (unknown code) or a role default is missing → `generateFurniture`/`computeBom`/`priceBom` never throw; warnings `furniture.archived_code`, `furniture.no_default_hardware`, error `furniture.unknown_code`, model still rendered. Test: Task 36 `catalogDrift.test.ts`.
4. **Malformed server input to the CLI:** invalid JSON, wrong types, future `schemaVersion`, unknown command, 2 MB+ documents → `{ ok: false }` (oversize plans: `{ ok: true }` with `valid: false` and `plan.too_large`) with exit code 0, never a crash or partial stdout. Test: Task 48 `cli.e2e.test.ts`.
5. **Out-of-order worker responses** while the user types quickly → only the latest request per method resolves; stale ones reject with `EngineWorkerStaleError` and never overwrite newer results; worker errors surface as rejections. Test: Task 49 `engineRpc.test.ts`.
